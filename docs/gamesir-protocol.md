# GameSir 2.4G 接收器（3537:103E）厂商通道笔记

实测环境：盖世小鸡「超新星」，2.4G 接收器 `USB\VID_3537&PID_103E\5FD0DF51`，
Xbox 模式，Windows 11 26100。工具：`tools/gs/gsprobe.py`（纯 ctypes，免编译）。

## 一、设备拓扑

接收器同时枚举出 5 个 HID 集合：

| usage page/usage | in | out | 说明 |
|---|---|---|---|
| 0x0001 / 0x0005 | 15 | 0 | 手柄输入报（`Controller (GameSir-Dongle)`），`IG_00` 那份 |
| 0x0001 / 0x0002 | 7 | 0 | 鼠标集合（query-only） |
| 0x0001 / 0x0006 | 9 | 2 | 键盘集合（query-only，带 `\kbd` 后缀） |
| 0x000C / 0x0001 | 3 | 0 | 消费类控制（音量等） |
| **0xFFA0 / 0x0001** | **64** | **32** | **厂商配置通道** |

另有 `XnaComposite` 的「支持 Windows 的 XBOX 360 手柄」（MI_00），那是 XInput 走的路。

## 二、报文格式（0xFFA0）

**下行（主机 → 接收器）**，output report **id 0x07**，固定 32 字节：

```
07  00  <len>  <cmd>  <param0> <param1> ... 
```

- `len` = cmd 及其后参数字节的总数（len=1 表示只有 cmd，没有参数）
- 只有 report id 0x07 可写，1~0x28 其余 id 一律 `ERROR_INVALID_PARAMETER(87)`

**上行（接收器 → 主机）**，input report **id 0x06**，固定 64 字节：

```
06  <datalen>  <len 回显>  <cmd 回显>  <param 回显> ...  <data...>
```

空闲时接收器以约 95 Hz 持续发 `06 00 00 ...`（全零心跳）。写出一条命令后
会先回一条 `06 <n> ...` 应答，然后继续心跳。

## 三、已确认的命令

| cmd | 参数 | 返回 datalen | 说明 |
|---|---|---|---|
| 0x01 | 无 | 0x04 | 返回 4 字节，实测全零（可能是固件/版本槽，未定） |
| 0x02 | 块索引 | 0x18 (24) | **读配置块**，24 字节定长 |

`cmd=0x02` 未给参数时返回 `datalen=0x13`(19) 全零。

### 配置块（cmd 0x02，参数 = 块索引）

- 0x00 ~ 0x29 有内容，0x2A 以后全零
- 每块 24 字节
- **0x1C 是动态块**：同一秒内连读三次值都不同，疑似实时状态（摇杆/扳机/包计数之类）
- 0x1D 看着像密钥/序列号：`58 56 53 4B 0B B9 D8 5F DE 9F AB 4B A9 2D 0E 89 0F D7`
- 0x00 里有 `1E 1E 32 32 46 46 64 64`（30/30/50/50/70/70/100/100），
  很像「电量分档 → 百分比」映射表，也像震动/灯效档位表，未定

### 原始样例

```
块 0x00: 00 00 00 00 00 00 01 32 05 00 1E 1E 32 32 46 46 64 64 00 32 00 00 00 00
块 0x02: 00 46 5F 90 64 14 06 00 0A 1E 14 32 00 46 32 5F 05 00 04 64 00 00 00 00
块 0x1C: 82 41 4A 64 1F 0D 00 00 68 00 1C C8 8C 68 03 1C 8C 0F 03 00 00 00 00
块 0x28: 00 41 85 64 49 00 00 40 40 40 40 40 00 00 01 01 40 00 00 00 00 00 00 00
```

## 四、为什么 WGI 的电量是假的

- XInput：`type=1 wired`，因为接收器自称有线
- `Windows.Gaming.Input` 的 `RawGameController.TryGetBatteryReport()`：
  `status=Discharging remain=1000 full=1000` → 恒 100%
- 这个 1000/1000 是 xusb22 那条链路上的固定值，不是真读数

真电量要么在 0xFFA0 的某个配置块里，要么需要充电/放电对比才能定位。

## 五、坑

**不要盲目扫 `cmd=0x02` 的块索引到 0xFF。** 实测扫到某一段时整个接收器从 USB 总线上消失
（`Get-PnpDevice` 里 Present=False，需要物理拔插才回来）。以后只在 0x00~0x2F 范围内试探。
